# ADR 0007 — 全幅无级拼贴布局引擎（确定性 Skyline 二维装箱）

- 状态：已接受
- 日期：2026-11-08
- 相关文件：`apps/desktop/src/lib/wall-layout.ts`、`apps/desktop/src/components/wall/MasonryWall.tsx`、`packages/design-tokens/src/tokens.ts`（`mosaic`）

## 背景

旧实现是 **12 列 CSS Grid + `grid-auto-flow: dense` + 六种固定跨度**
（hero / portrait-lg / portrait-sm / wide / resume / dynamic）。它有三个无法通过
「把 12 列改成 24 列」解决的问题：

1. **尺寸天然离散**：Grid 只能表达整数列跨度，磁贴宽度必然是列宽的整数倍。
   列数再多也只是更细的档位，不是「无级」。
2. **dense 回填会打乱顺序**：用户拖拽后的自定义顺序会被 dense 流重新排布，
   与「自定义排序保持布局」冲突。
3. **无法产生真正的二维穿插构图**：Grid 的行高是统一的，超大竖版与超大横幅
   不能在同一行互相咬合；也无法在超大横幅右侧形成竖版填补。

同时，旧渲染层是「每批追加 24 个 DOM」，1000 条时会挂载全部节点，
不属于虚拟化。

## 决策

自研**确定性 Skyline（最左最低 + 宽度试探）二维装箱引擎**，输出绝对像素坐标。

具体做法：

- **连续尺寸**：目标宽高比由媒体类型、素材比例、权重与 id hash 连续插值得到；
  横幅按宽度驱动、竖版按高度驱动，尺寸是画布宽度的连续比例函数，
  再用 `emphasis^1.5` 拉开大中小反差。没有枚举档位。
- **权重**：媒体类型 / 最近添加 / 评分 / 收藏 / 续播 / 排序位置 / 自定义权重 /
  确定性 hash 抖动 / `sin` 连续节奏脉冲，合计为 0..1 的 `emphasis`。
- **装箱**：维护一条 skyline（每个 x 区间当前底部 y）。放置时遍历区间起点，
  取覆盖区间内最大 y，选「y 最小、x 最小」的位置；对 skyline 的每个凹口
  生成「刚好填满」的宽度候选（用 id hash 门控部分磁贴参与），
  让大磁贴留下的空隙被后续小磁贴自然回收。
- **确定性**：全部随机性来自 `hashString(mediaId|salt)`；时间权重以数据集中
  最大 `addedAt` 为固定基准，不调用 `Date.now()`。同一批数据多次计算结果完全一致。
- **虚拟化**：每个磁贴有绝对 y，容器高度固定为 `canvasHeight`；
  渲染层按滚动区间 + overscan 过滤，首屏挂载量与总条目数无关。

## 备选方案与不采用理由

| 方案 | 不采用理由 |
|---|---|
| 把 Grid 从 12 列提高到 24/48 列 | 仍是离散档位，且 dense 回填仍会打乱自定义顺序；属于「用提高列数冒充无级」 |
| 现成 Masonry 库（列式瀑布流） | 按列堆叠，无法同屏混排超大横幅与超大竖版，构图仍是瀑布流 |
| 固定若干「尺寸档 + 随机打散」 | 只是把六档换成十二档，尺寸不连续，且会出现明显重复周期 |
| 商用 2D bin-packing 库 | 目标是「最小化容器高度」，会把磁贴压成近似等大以填满，破坏视觉层次；且引入额外依赖与许可审查成本 |
| 手写物理/力导向布局 | 结果不确定、不可复现，无法稳定支持拖拽排序与截图回归 |

选择自研 Skyline 的关键理由：它同时满足**零重叠**、**尺寸连续**、
**可确定性复现**、**可回收空洞**、**输出绝对坐标（便于虚拟化）** 五个约束，
而上述任何现成方案都至少违反其中一个。

## 后果

正面：

- 幕墙可以铺满应用内容区左右边缘（`.page-scroll.is-fullbleed` 左右 padding 为 0），
  不存在固定 40px 页面留白与 232px 侧栏挤压。
- 首屏只挂载 16–19 个磁贴（1000 条数据时实测 18 个），滚动性能与数据量解耦。
- 布局耗时 1000 条约 13 ms，且完全可复现，便于截图回归与单元测试。
- 用户拖拽排序只改 `customOrder`，布局按新顺序重算，不依赖 dense 流。

负面 / 待解决：

- Skyline 装箱不保证全局最优，极端数据下仍可能残留窄缝；
  这些缝隙由后续磁贴的凹口候选回收，但不做全局重排（会破坏阅读顺序）。
- 凹口候选会让部分磁贴偏离「理想宽高比」，属于有意的构图取舍。
- 「无级」的视觉验收依赖真人判断，自动化测试只能验证连续性与零重叠。

## 与五层能力模型无关

本 ADR 只涉及 UI 布局，不改变任何播放/HDR/Dolby 能力声明：
libmpv 仍未集成，原生视频 Surface 与 HDR/Dolby 输出仍未验证。
